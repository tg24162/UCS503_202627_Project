# **WEEK 2 - Database Schema, Models, and Initial Migration**

### **What I Did This Week:**

1. **Designed the schema on paper**

   * Five tables: User, Category, Transaction, RecurringPayment, Target.
   * Mapped every requirement field to a column and annotation: amount → Numeric(12,2), priorities → JSONB, payment method/source/frequency/period → Postgres enums, timestamps → DateTime(timezone=True).
2. **Wrote the models (`models.py`)**

   * SQLAlchemy 2.0 typed style (Mapped\[...] / mapped\_column) with a shared TimestampMixin (created\_at/updated\_at with `server\\\_default=now()`).
   * UUID primary keys for user-owned data, integer PK for Category.
3. **Added foreign keys and indexes**

   * Explicit ondelete behavior: CASCADE on user delete, SET NULL for category references.
   * Indexes on every `user\\\_id`, plus composite indexes `(user\\\_id, transaction\\\_date)` and `(user\\\_id, category\\\_id)` on transactions, the hot paths for later analytics queries.
4. **Generated the first migration**

   * Ran `alembic init`, configured it, and generated the migration with `alembic revision --autogenerate -m "initial models"`.
   * **Problem:** First enum columns had no `name=` argument, so Alembic creates inline/anonymous enums that are a pain to alter later. Fixed by giving every enum an explicit database name (`payment\\\_method`, `recurring\\\_frequency`, etc.).
5. **Applied the migration and seeded data**

   * `alembic upgrade head` → Running upgrade -> f30349e4a756, initial models.
   * Wrote and ran `seed.py`, inserting Food, Transport, Bills, Shopping, Entertainment.
   * Verified by querying the database directly: listed all public tables (alembic\_version, categories, recurring\_payments, targets, transactions, users) and confirmed the 5 category rows existed.
