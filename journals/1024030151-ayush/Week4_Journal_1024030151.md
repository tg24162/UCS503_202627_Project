# **WEEK 4 - Manual Entry CRUD**

### **What We Did This Week:**

1. **Built the transactions router**

   * Create endpoint forces `source=manual`, `ocr\_confidence=null`, `needs\_review=false`; the schema only carries amount/date/item/category/payment/place.
   * List endpoint supports `category\_id`, `date\_from`, `date\_to`, `limit`, `offset`.
   * **Problem:** The list endpoint originally returned everything unbounded. Future users with thousands of receipts would hang the API. Added a limit (max 100) / offset and a total count in the response.
2. **Did a security pass**

   * No endpoint ever trusts a `user\_id` from the request body; every query filters by the authenticated user's id from the token.
   * `GET /transactions/{id}`, `PUT`, and `DELETE` return 404 (not 403) when a record isn't found or isn't owned, a deliberate choice so other users' ids can't be probed.
3. **Built the recurring payments router**

   * Create, list (active-only by default + `include\_inactive` flag), update, and soft delete (`is\_active=False` instead of a real DELETE).
   * Cancelled subscriptions stay in history, matching the product's "cancellation prompt" requirement.
4. **Built the categories router**

   * Lists the seeded defaults.
   * **Problem:** Money values sent as JSON floats were passing through schemas typed as float and reaching the model. Aligned the schema types with the model's Decimal (`gt=0` constraint) so amounts stay string-exact through the API ("450.75", never 450.750000001).
5. **Improved schemas and query performance**

   * Separate Pydantic v2 Create/Update/Response schemas so raw ORM objects are never serialized directly.
   * `exclude\_unset` on the update schemas so a partial PUT (e.g., only `item\_name`) doesn't wipe other fields.
   * List queries eager-load the category relation (`selectinload`) to avoid a second query per row (N+1).
