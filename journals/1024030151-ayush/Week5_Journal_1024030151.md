# **WEEK 5 - End-to-End Testing + Quick UI Prototype**

### **What We Did This Week:**

1. **Wrote the end-to-end test (`e2e\_test.py`)**

   * Full flow: signup → me → login → empty list → create tx → get → update → list/filter → delete → 404 confirm → categories → create recurring → update → soft-cancel → hidden/visible flags → 401 with no token.
2. **Fixed Windows / test-output issues**

   * **Problem:** The 204 No Content response has an empty body, so `resp.json()` threw `JSONDecodeError`. Guarded the JSON parsing so status-only checks work.
3. **Resolved the DB credentials problem**

   * **Problem:** From one session to the next, Postgres started rejecting the password that had worked the day before (`FATAL: password authentication failed for user "postgres"`), and every endpoint returned 500/401.
   * After confirming the service was listening, it turned out the DB password had been changed on the server. Updated `.env` and restarted the server, since the running process had cached the old engine/credentials and a `.env` edit alone wasn't enough.
4. **Built a quick Streamlit frontend (`app.py`)**

   * Login/signup tabs (signup includes the survey fields), transactions tab (add, filter, edit, delete), recurring-payments tab (add, cancel, edit), and a categories view.
   * Used Streamlit's AppTest to render the logged-out view, then programmatically signed up and confirmed the logged-in tabs render with zero exceptions.
   * Ran a full live-HTTP check against the running uvicorn server: 12/12 checks passed (signup → login → tx CRUD → recurring cancel → inactive flag → me).
5. **Cleaned up ports and test data**

   * **Problem:** Starting uvicorn gave `ERROR: \[WinError 10013] An attempt was made to access a socket in a way forbidden by its access permissions.` Earlier background test servers were still holding ports 8000/8501. Fixed by finding the PIDs (`netstat -ano`) and killing them (`Stop-Process`).
   * Cleaned up all test users from the DB so no `\*@example.com` accounts were left behind.
