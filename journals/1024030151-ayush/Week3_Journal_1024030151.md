# **WEEK 3 - Authentication (JWT + bcrypt)**

### **What I Did This Week:**

1. **Implemented the auth endpoints**

   * `POST /auth/signup` (create user + return token), `POST /auth/login`, and `GET /auth/me`.
   * Normalized emails to lowercase on signup/login so A@X and a@x can't create duplicate accounts.
2. **Fixed the bcrypt / passlib incompatibility**

   * **Problem:** bcrypt 5.0.0 was already in the environment, and passlib 1.7.4 crashes with it. Hashing errored with `AttributeError: module 'bcrypt' has no attribute '\_\_about\_\_'` and `ValueError: password cannot be longer than 72 bytes, truncate manually`.
   * It wasn't just a log warning; `CryptContext.hash()` blew up entirely.
   * Root cause from the stack trace: passlib reads `bcrypt.\_\_about\_\_.\_\_version\_\_`, which bcrypt 4.1 removed. Passlib is unmaintained, so the clean fix was pinning `bcrypt==4.0.1`.
   * Re-verified the hash + verify round-trip in a REPL before wiring it into the API (hashed: `$2b$12$...`, verify ok: True, verify bad: False).
3. **Created the JWT flow**

   * PyJWT token carries `sub` (user id), `iat`, and a 24-hour `exp`.
   * **Problem:** Initially planned to put user data inside the token to avoid DB lookups, then realized that's the wrong pattern. The token should only identify; the DB is the source of truth, so password changes/logins can't be bypassed by a stale token. Kept it to `sub` only.
   * Generated signing secrets and stored `JWT\_SECRET`, `JWT\_ALGORITHM`, `JWT\_EXPIRE\_MINUTES` in `.env` (kept out of git).
4. **Built the `get\_current\_user` dependency**

   * Uses HTTPBearer, decodes the token, looks up the user, and raises 401 with `WWW-Authenticate` on any failure.
   * Proper status codes: 201 on signup, 409 on duplicate email, 401 on bad login, 422 via Pydantic validation.
5. **Wired up and tested**

   * Wired the auth router into `main.py` and manually tested signup → login → me with curl.
   * **Problem (500 on signup):** The server was hidden in a background window, so there were no logs to read. Learned to reproduce locally (TestClient) to get the real traceback instead of debugging the live server blind.
